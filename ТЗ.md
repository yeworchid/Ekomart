# Техническое задание на семестровую работу

## Проект

**Название:** Ekomart  
**Тип:** веб-приложение на ASP.NET Core MVC  
**Предметная область:** интернет-магазин с пользовательской витриной, корзиной, заказами, подписками и административной панелью.

Цель проекта — реализовать рабочее MVC-приложение для демонстрации основных пользовательских и административных сценариев интернет-магазина с разграничением доступа, нормализованной БД, подписками, AJAX-операциями, логированием и развёртыванием.

## Используемые шаблоны

- **Ekomart** — основа пользовательской части: главная, каталог, карточка товара, корзина, оформление заказа, профиль.
- **Vuexy ASP.NET Core MVC** — основа административной панели: layout, меню, таблицы, формы, dashboard.

Шаблоны используются выборочно. Демо-модули, не относящиеся к требованиям проекта, не переносятся.

Ниже указаны конкретные страницы live demo, которые используются как визуальная и структурная основа. Если точного аналога в live demo нет, страница реализуется как собственная MVC-страница проекта без ссылки на демо.

## Архитектура

Проект строится по слоистой архитектуре / Clean Architecture:

| Слой | Ответственность |
| --- | --- |
| `Domain` | Доменные сущности: товары, категории, заказы, подписки, логи. |
| `Application` | DTO, интерфейсы сервисов, контракты бизнес-сценариев. |
| `Infrastructure` | EF Core, PostgreSQL, Identity, seed-данные, реализации сервисов. |
| `Web` | ASP.NET Core MVC, Razor Views, контроллеры, админ-область, middleware, SignalR. |
| `Seeder` | Наполнение БД тестовыми данными. |

Архитектура предусматривает возможность замены хранилища данных и добавления другого пользовательского интерфейса с минимальными изменениями основного кода.

## Роли

| Роль | Возможности |
| --- | --- |
| Гость | Просмотр главной, каталога, карточек товаров, регистрация и вход. |
| User | Корзина, оформление заказа, профиль, история заказов, продление подписки. |
| Manager | Админ-панель для работы с товарами, категориями, заказами, подписками и логами. |
| Admin | Полный доступ, включая управление пользователями и ролями. |

Авторизация реализуется через ASP.NET Core Identity. Для доступа к админке используются роли и политики.

## Система подписок

В проекте реализуются минимум два тарифа: `Basic` и `Plus`.

У тарифа есть:

- название;
- описание;
- стоимость;
- срок действия;
- процент скидки на заказ;
- список доступных функций;
- признак активности.

Пользователь оформляет или продлевает подписку виртуально. Подписка имеет простое практическое действие: если у пользователя есть активный тариф, при оформлении заказа применяется скидка от суммы товаров. Для `Basic` используется скидка 3%, для `Plus` — скидка 7%. После истечения срока подписки скидка не применяется до следующего продления.

Скидка фиксируется в заказе как процент и сумма скидки, чтобы история заказов не менялась после редактирования тарифов в админ-панели.

Подписки можно изменять из админ-панели: добавлять, редактировать, отключать и удалять тарифы.

## База данных

Основная реляционная БД: **PostgreSQL**.

Предметные таблицы:

- `Categories`;
- `Products`;
- `CartItems`;
- `Orders`;
- `OrderItems`;
- `SubscriptionPlans`;
- `UserSubscriptions`;
- поля заказа для процента и суммы подписочной скидки;
- `AuditLogs`.

Таблицы ASP.NET Core Identity используются отдельно и не входят в предметную модель.

Дополнительно планируется использовать MongoDB для технических логов или кэша. Предметные данные магазина в MongoDB не хранятся.

## AJAX и realtime

В проекте используются AJAX-операции:

- обновление каталога после фильтрации/пагинации;
- добавление товара в корзину;
- изменение количества товара;
- удаление товара из корзины;
- получение счётчика корзины;
- продление подписки;
- смена статуса заказа.

SignalR используется для уведомлений о создании заказа и изменении статуса заказа.

## Безопасность и валидация

Реализуется:

- ASP.NET Core Identity;
- роли `User`, `Manager`, `Admin`;
- политики доступа;
- antiforgery для форм и AJAX;
- серверная и клиентская валидация форм;
- безопасный вывод данных через Razor encoding;
- параметризованные запросы EF Core;
- аудит запросов и пользовательских действий;
- собственные страницы ошибок `403` и `404`.

## Развёртывание и организационные требования

В проекте будут:

- README с инструкцией запуска;
- Dockerfile и Docker Compose;
- EF Core migrations;
- seed-данные для ролей, пользователей, товаров, категорий и подписок;
- тестовые учётные записи;
- регулярные коммиты;
- таск-трекер или issue board;
- развёртывание на хостинге до финальной сдачи.

## Не входит в объём проекта

Не реализуются:

- реальные платежные шлюзы;
- реальные службы доставки;
- мобильные приложения;
- микросервисная архитектура;
- мультивендорный marketplace;
- сложный складской и бухгалтерский учёт;
- чаты, календарь, email-клиент, kanban и другие демо-модули Vuexy;
- блог, wishlist, сравнение товаров и vendor-страницы из Ekomart;
- социальная авторизация;
- реальная отправка email;
- двухфакторная авторизация.

Безопасность в рамках семестровой работы закрывается Identity, ролями, политиками доступа, antiforgery, валидацией, безопасным выводом данных и аудитом.
